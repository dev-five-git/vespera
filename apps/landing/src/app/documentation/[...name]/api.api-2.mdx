# Route Attribute & Extractors

`#[vespera::route]` marks a `pub async fn` as an HTTP handler. Vespera reads the function signature to extract path parameters, query parameters, request body, and response types for the OpenAPI spec.

## Route Attribute Parameters

```rust
#[vespera::route(
    get,                              // HTTP method (default: get)
    path = "/{id}",                   // Path suffix (appended to file-based prefix)
    tags = ["users", "admin"],        // OpenAPI tags
    description = "Get user by ID"    // OpenAPI operation description
)]
pub async fn get_user(Path(id): Path<u32>) -> Json<User> { ... }
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| method | `get`, `post`, `put`, `patch`, `delete`, `head`, `options` | `get` | HTTP method |
| `path` | string | `""` | Path suffix appended to the file-based prefix |
| `tags` | string array | `[]` | OpenAPI tags for grouping in Swagger UI |
| `operation_id` | string | function name | OpenAPI `operationId`. Colliding default ids are module-qualified; two identical explicit ids are a compile error |
| `summary` | string | first paragraph of the doc comment | OpenAPI operation summary |
| `description` | string | doc comment after its first paragraph | OpenAPI operation description (the whole doc comment when `summary` is given). An explicit value disables doc-comment extraction |
| `status` | `2xx` integer | `200` | Success status, e.g. `status = 204`; `204` / `304` document no body. A non-`2xx` value is a compile error |
| `error_status` | integer array | none | Extra schema-less error statuses, e.g. `error_status = [404]` |
| `responses` | `[(status, Type)]` | none | Typed error bodies, e.g. `responses = [(404, NotFoundError)]`; `Type` must implement `Schema` |
| `security` | string array | document default | Security requirements, e.g. `security = ["bearerAuth"]`; `security = []` marks the operation unauthenticated |
| `headers` | array of `{ name, required?, description? }` | none | Header parameters read by custom extractors; `required` defaults to `false` |
| `request_example` | JSON string | none | Request body example; invalid JSON is emitted as a string value |
| `response_example` | JSON string | none | `200` response example; invalid JSON is emitted as a string value |
| `deprecated` | bare flag | off | Marks the operation `deprecated: true` (`#[deprecated]` on the handler does the same) |

```rust
#[vespera::route(
    put,
    path = "/{id}",
    tags = ["users"],
    operation_id = "updateUser",
    summary = "Update a user",
    security = ["bearerAuth"],
    headers = [{ name = "X-Trace-Id" }],
    request_example = r#"{"name":"Alice"}"#,
    deprecated
)]
pub async fn update_user(...) -> ... { ... }
```

Without `summary` / `description`, the handler's doc comment is used: its first paragraph becomes the `summary`, the remaining paragraphs the `description`.

## Examples

### Path Parameters

```rust
// Single path param
#[vespera::route(get, path = "/{id}")]
pub async fn get_user(Path(id): Path<u32>) -> Json<User> { ... }

// Multiple path params via struct
#[derive(Deserialize)]
pub struct PostParams {
    pub user_id: u32,
    pub post_id: u32,
}

#[vespera::route(get, path = "/{user_id}/posts/{post_id}")]
pub async fn get_post(Path(params): Path<PostParams>) -> Json<Post> { ... }
```

The axum 0.7 notation is accepted too and normalized at compile time: `path = "/users/:id/files/*rest"` registers `/users/{id}/files/{*rest}` and is documented as `/users/{id}/files/{rest}`. A malformed path (unbalanced braces, an empty `{}` / `:`, a duplicate parameter name, a catch-all that is not the last segment) is a compile error on the path literal.

### Query Parameters

```rust
#[derive(Deserialize, Schema)]
pub struct ListUsersQuery {
    pub page: Option<u32>,
    pub limit: Option<u32>,
    pub search: Option<String>,
}

#[vespera::route(get)]
pub async fn list_users(Query(q): Query<ListUsersQuery>) -> Json<Vec<User>> { ... }
```

### JSON Body

```rust
#[derive(Deserialize, Schema)]
pub struct CreateUserRequest {
    pub name: String,
    pub email: String,
}

#[vespera::route(post)]
pub async fn create_user(Json(req): Json<CreateUserRequest>) -> Json<User> { ... }
```

### Validated Body (with 422)

```rust
use vespera::Validated;
use garde::Validate;

#[derive(Deserialize, Schema, Validate)]
pub struct CreateUserRequest {
    #[garde(length(min = 3, max = 32))]
    pub username: String,
    #[garde(email)]
    pub email: String,
}

#[vespera::route(post)]
pub async fn create_user(
    Validated(Json(req)): Validated<Json<CreateUserRequest>>,
) -> Json<User> { ... }
```

### State (Ignored by OpenAPI)

```rust
#[vespera::route(get)]
pub async fn list_users(
    State(db): State<DbPool>,   // ignored by OpenAPI
    Query(q): Query<ListQuery>, // included in OpenAPI
) -> Json<Vec<User>> { ... }
```

### Error Responses

```rust
#[derive(Serialize, Schema)]
pub struct ApiError {
    pub message: String,
}

#[vespera::route(get, path = "/{id}")]
pub async fn get_user(
    Path(id): Path<u32>,
) -> Result<Json<User>, (StatusCode, Json<ApiError>)> {
    if id == 0 {
        return Err((
            StatusCode::NOT_FOUND,
            Json(ApiError { message: "Not found".into() }),
        ));
    }
    Ok(Json(User { id, name: "Alice".into() }))
}
```

A handler returning `Result<_, E>` documents a single inferred `400` error, because the macro cannot read the runtime `StatusCode`. Declare the real statuses with `responses` (typed bodies, a JSON `$ref` per status) and/or `error_status` (schema-less). As soon as any of them is present the explicit set is authoritative and the inferred `400` is dropped unless you list it; a typed `responses` entry wins over `error_status` for the same code.

```rust
#[vespera::route(get, path = "/{id}", responses = [(404, ApiError)])]
pub async fn get_user(...) -> Result<Json<User>, (StatusCode, Json<ApiError>)> { ... }

// 204 success + 404 error — no 200, no 400
#[vespera::route(delete, path = "/{id}", status = 204, error_status = [404])]
pub async fn delete_user(Path(id): Path<u32>) -> Result<StatusCode, (StatusCode, String)> { ... }
```

## Handler Requirements

- Must be `pub async fn` — private or non-async functions are ignored
- Must have `#[vespera::route]` attribute
- Can live anywhere in `src/routes/` (or your configured `dir`)
- The URL is: **file path prefix + `path` attribute value**

# Migrating to 0.6

The 0.6 release is a hardening pass: OpenAPI output becomes more faithful to what serde actually serializes, `Validated<T>` reports deserialization errors through the `422` envelope, and the in-process / JNI transport gets default resource limits. This page lists every change that can affect an existing 0.5 application.

## OpenAPI Output

- **Untagged enums** emit `anyOf` (previously `oneOf`).
- **Tuple / newtype structs, fixed-size arrays and tuples** get real `array` / inner schemas instead of a generic object.
- **`skip_serializing` / `skip_serializing_if` fields** are no longer `required`.
- **Tagged newtype variants**, variant-level `skip` / `other`, and `Arc` / `Rc` / `Cow` / `NonZero*` wrappers are supported.
- **Plain tuple returns** (e.g. `(StatusCode, Json<T>)`) and body-less `error_status` codes are documented.
- **Colliding default `operationId`s** are module-qualified. Two explicit, identical `operation_id = "..."` values are now a compile error.
- **Known `headers::*` `TypedHeader` parameters** use the real HTTP header name.
- **`Path<Struct>`** parameters are typed per field (serde names). **`Query<Struct>`** drops `skip` / `skip_deserializing` fields, expands `flatten`, and array fields carry `style: form, explode: true`.
- **Opaque and raw bodies:** `impl IntoResponse` / `Response` / `Redirect` responses are description-only; `Html<T>` is `text/html`, `Sse` is `text/event-stream`, `Bytes` / `Vec<u8>` are `application/octet-stream`; `Option<Json<T>>` request bodies are `required: false`.
- **Type mappings:** `serde_json::Value` is `{}`, `std::time::Duration` is `{secs, nanos}`; `IpAddr` / `SocketAddr` / `PathBuf` are `string`, `Ipv4Addr` / `Ipv6Addr` carry `format: ipv4` / `ipv6` and `url::Url` `format: uri` (previously a `Schema` assertion error); `{*rest}` wildcards are documented as `{rest}`.
- **`Validated` / `ValidatedWith`:** a route whose `Validated<...>` argument follows a `Path<T>` argument now documents its `422` response. `ValidatedWith<C, T>` arguments now document their request body / query parameters and `422` (previously both were missing). A `Validated` payload without `garde::Validate` (a rule-less `Schema` struct or an enum) is reported with a dedicated compile error at the argument.
- **`#[garde(...)]` rules are documented:** `length` (`chars` mode, or `min = 1`; item and property counts), `range`, `email` / `url` / `ip*`, `pattern` / `prefix` / `suffix` / `contains` / `ascii`, and `inner(...)` on `items` now appear in the schema of a `#[derive(Schema, garde::Validate)]` type. `#[schema(...)]` and `#[garde(...)]` rules on `Query<Struct>` / `Path<Struct>` fields reach the parameter schemas. Snapshots of such types change.
- **Custom serde conversions:** a field with `#[serde(with / serialize_with / deserialize_with)]` is documented as any value (`{}`) with a note instead of its Rust type (add `#[schema(value_type = T)]` for the real shape); container `#[serde(into = "T")]` documents responses as `T` and `from` / `try_from` documents requests as `T`; an `Option` read by a custom deserializer is `required` in requests. SeaORM `Json` / `JsonValue` columns are `{}` (previously `type: object`), and `schema_type!` maps `JsonValue` to `serde_json::Value`.
- **Serde attributes:** `flatten` on `Option<T>` makes `T`'s fields optional; an enum's `rename_all` no longer renames struct-variant fields; `rename_all_fields` and `deny_unknown_fields` (`additionalProperties: false`) are supported.

## Served URLs and Build Output

- **Explicit route paths are used verbatim.** `#[route(path = "/my_route")]` now serves `/my_route` (previously kebab-cased to `/my-route`). Only segments derived from file and module names are kebab-cased. Update clients, or write the path in kebab-case yourself.
- **`openapi = "..."` output location:** a relative path resolves against the crate's `CARGO_MANIFEST_DIR`, so workspace members write `openapi.json` next to their own `Cargo.toml`. The cache directory honours `CARGO_TARGET_DIR`.
- **`Serve`:** `serve()` provides `ConnectInfo<SocketAddr>`, and the trait gained `serve_with_graceful_shutdown(addr, signal)` — custom implementors must add it.
- **Cron:** jobs start once per process even if `create_app()` runs several times, and run on a dedicated `vespera-cron` thread when no Tokio runtime is present.
- **`multipart` cargo feature:** multipart support (`vespera::multipart`, `vespera::tempfile`, `#[derive(Multipart)]`, `schema_type!(..., multipart)`) moved behind the new `multipart` feature. It is in the default features, so nothing changes unless you build with `default-features = false` — then add `features = ["multipart"]` if you use multipart (otherwise `#[derive(Multipart)]` is a compile error that names the feature). `axum-extra/multipart` moved from the default list into this feature too.

### New compile errors

Code that previously compiled with a silently wrong spec now fails at compile time:

- an unknown security scheme referenced by `security = [...]` (checked after `merge`),
- a malformed `#[schema(...)]` attribute,
- an internally tagged enum (`#[serde(tag = "...")]`) with a scalar newtype payload,
- duplicate explicit `operation_id`s.

## OpenAPI Accuracy Changes

These changes alter the generated document of an existing application without any code change:

- **No default server.** `servers: [{ url: "http://localhost:3000" }]` is no longer emitted; without `servers = [...]` / `VESPERA_SERVER_URL` the document omits `servers`, so Swagger UI and clients call the origin that serves the spec. Add `servers = [{ url = "http://localhost:3000" }]` to keep the old output.
- **Summary from doc comments.** The first paragraph of a handler's doc comment becomes the operation `summary`, the remaining paragraphs the `description` (previously the whole comment was the `description`). An explicit `summary = "..."` keeps the whole doc comment as the description; an explicit `description = "..."` disables doc-comment extraction.
- **`info.description`** defaults to the crate's `description` in `Cargo.toml`.
- **Renamed schemas** (`#[schema(name = "UserDto")]`) are referenced by their custom name instead of an inline `{ "type": "object" }`.
- **Recursive generics** such as `Tree<i32>` (`struct Tree<T> { children: Vec<Tree<T>> }`) become components named after the instantiation — base name plus each type argument joined with `_` (`Tree_i32`, `Tree_Vec_User`). Non-recursive generics (`Page<User>`) are still inlined.
- **Unit and alias returns.** `Result<(), E>` and `()` document an empty `200` without `content`; `axum::response::Result<T>` documents its `ErrorResponse`; `type ApiResult<T> = Result<Json<T>, AppError>` aliases are expanded; an unresolvable return type is documented by description only.
- **serde naming.** `rename_all` now applies serde's exact field and variant rules (variant `XMLParser` with `camelCase` is `xMLParser`), and `rename(serialize = "..", deserialize = "..")` uses the deserialize name for request-only contexts (query / path parameters).
- **More annotations**: `#[deprecated]` handlers and fields emit `deprecated: true`, `skip_deserializing` fields `readOnly`, `skip_serializing` fields `writeOnly`; doc comments keep Markdown indentation; per-variant `#[serde(untagged)]` emits an `anyOf`.
- **Request views (`{Name}Input`).** When serde reads a type differently than it writes it — `#[serde(default)]` on a field or the container, `skip_deserializing` or `skip_serializing` (not both), `rename(deserialize = "..")` / `rename_all(deserialize = "..")` differing from the serialize side, or a field whose type has its own input view — `Json` / `Form` / `TypedMultipart` request bodies now reference an extra `{Name}Input` component: defaulted fields are not `required`, `skip_deserializing` fields are absent, and keys use the deserialize name. The `{Name}` component (the response view) is unchanged. No `Input` component is emitted when the two views are identical or no request body uses the type. `#[schema(name = "X")]` gives `XInput`; when a type already owns that name the first free `XInput2`, `XInput3`, … is used. Generated clients will see new request types for these bodies.
- **Query parameters** honour container `#[serde(default)]`, `Option<Query<T>>` (all optional) and destructured `Query(Filter { .. })` / `_` patterns.

### New compile errors (OpenAPI accuracy)

- `#[route(responses = [(404, NotFound)])]` where `NotFound` does not implement `Schema` (previously a dangling `$ref`).
- A `#[route]` handler inside an inline `mod name { .. }` block of a route file (it could never be mounted; move it to its own file).

Route modules declared behind `#[cfg(...)]` that are compiled out, and `#[cfg]`-gated handlers, are now skipped instead of producing an unresolved path.

## `Validated<T>` Deserialization Errors

`Validated<Json<T>>`, `Validated<Form<T>>`, `Validated<Query<T>>` and `Validated<Path<T>>` now turn **deserialization failures** (wrong type, missing field, unparsable value) into `422 Unprocessable Entity` with the same `{"errors":[{"path","message"}]}` envelope as rule violations. Previously these returned axum's plain-text rejections (`422` / `400`). Malformed JSON syntax (`400`) and `415` content-type errors are unchanged. See [Validated & 422](/documentation/concept/concept-3).

Streaming dispatch also changed:

- `dispatchStreaming` / `dispatchFullStreaming` throw `IOException` when the response fails **after** body bytes were written (previously a synthetic `500` header after a partial body).
- `dispatchStreaming` hoists `422` `validation_errors` into the wire header like the buffered modes.

## Java Bridge (`vespera-bridge`)

1. **Spring is a provided dependency.** The bridge no longer exports `spring-boot-starter-web` / `jackson-databind`; declare them in your app if you relied on them transitively. Spring Boot 3.5 and 4 are supported.
2. **`HEAD` keeps the real `Content-Length`** of the matching `GET` instead of `Content-Length: 0`.
3. **Native library extraction** is per-user, permission-checked and content-addressed (`vespera-native-<sha256-prefix>/` under `vespera.native.dir` / `VESPERA_NATIVE_DIR` / `<java.io.tmpdir>/vespera-<user.name>`) and reused across restarts.
4. **Autoconfiguration** is an `@AutoConfiguration` that also requires Spring MVC and the servlet API on the classpath.
5. **The new `configure*` methods return `boolean`** (`false` when the native side already fixed the value). `configureStreaming(int, int)` keeps its `void` signature.
6. **Upgrade the JAR and the native library together.** A new bridge JAR paired with a cdylib built against an older `vespera` crate binds the `configure*0` JNI hooks to the wrong signatures — rebuild the Rust library whenever you upgrade `vespera-bridge`.

7. **The app-selection header is client-controlled and no longer forwarded.** Restrict reachable apps with `vespera.bridge.exposed-apps` (unlisted names get `404` without dispatch); Rust handlers no longer see `X-Vespera-App`.
8. **Header values use a Latin-1 byte mapping** in both directions, so non-ASCII response header values are no longer dropped.
9. **Consumed form bodies are rebuilt.** `application/x-www-form-urlencoded` bodies already read by Spring (`FormContentFilter`, `CsrfFilter`) are reconstructed from the request parameters.
10. **Forwarded path:** the servlet context path, a prefix servlet mapping and `;` path parameters (e.g. `;jsessionid`) are stripped.
11. **Request ids:** responses carry `X-Request-Id` by default (`vespera.bridge.request-id.enabled` / `.header`).
12. **Proxy-generated errors** are `text/plain` (like Rust's `error_wire`) instead of Spring error pages; the unknown-app `404` no longer echoes the app name. `ASYNC` responses get no `Range` handling.
13. **Oversized buffered responses answer `500`, not `413`.** `vespera.bridge.max-buffered-response-bytes` (default 64 MiB) is forwarded to the native buffered-response cap unless `vespera.bridge.native.max-buffered-response-bytes` (or its sysprop/env) sets it.
14. **CORS preflights reach Rust by default.** `vespera.bridge.cors=rust` routes `OPTIONS` preflights to the Rust router (configure a `tower_http` `CorsLayer` there); set `vespera.bridge.cors=spring` to keep Spring MVC's CORS handling.
15. **Proxy errors are generic.** Unexpected failures answer `vespera dispatch failed` (details in the WARN log with the request id); a missing native library answers `503`.
16. **Bounded app names.** `DispatchEvent.app()` and the `app` metric tag report `UNKNOWN` for client-selected app names not known to be registered.
17. **Version check.** `VesperaBridge.init` fails when the native library's `major.minor` differs from the bridge's; `-Dvespera.native.versionCheck=warn` or `off` relaxes it.

### Gradle Plugin

- `publishPlugins` fails without Plugin Portal credentials.
- `cargoBuild` is now a `CargoBuildTask` instead of an `Exec`; build scripts that configure it as `Exec` must be updated.
- A missing `Cargo.lock` no longer fails the build; `extraNativeLibs` and `targets` add multi-platform jars.
- A hyphenated `crateName` now works (new optional `packageName` / `libName`), `bridgeVersion` defaults to the matching bridge release, and `cargoSourceRoots` is ignored.

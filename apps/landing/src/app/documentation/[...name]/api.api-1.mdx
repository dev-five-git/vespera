# vespera! Macro

The `vespera!()` macro is the entry point for every Vespera application. It scans your route folder at compile time, builds an `axum::Router` with all discovered handlers, and optionally writes an OpenAPI 3.1 spec file.

## Full Parameter Reference

```rust
let app = vespera!(
    dir = "routes",                    // Route folder (default: "routes")
    openapi = "openapi.json",          // Output path (writes file at compile time)
    title = "My API",                  // OpenAPI info.title
    version = "1.0.0",                 // OpenAPI info.version (default: CARGO_PKG_VERSION)
    description = "Pet store API",     // OpenAPI info.description (default: Cargo.toml description)
    summary = "Pets",                  // OpenAPI info.summary
    terms_of_service = "https://example.com/terms",  // info.termsOfService (http(s) URL)
    contact_name = "API Team",         // info.contact.name
    contact_url = "https://example.com/support",     // info.contact.url (http(s) URL)
    contact_email = "api@example.com", // info.contact.email
    license = "MIT OR Apache-2.0",     // info.license.identifier (SPDX); also the name
                                       //   unless license_name is set
    // license_name = "Proprietary", license_url = "https://example.com/license",
                                       //   non-SPDX license: name + url (excludes `license`)
    docs_url = "/docs",                // Swagger UI endpoint
    redoc_url = "/redoc",              // ReDoc endpoint
    spec_url = "/openapi.json",        // Raw OpenAPI JSON endpoint (application/json)
    servers = [                        // OpenAPI servers array
        { url = "https://api.example.com", description = "Production" },
        { url = "http://localhost:3000",   description = "Development" }
    ],
    security_schemes = [               // OpenAPI components.securitySchemes
        { name = "bearerAuth", type = "http", scheme = "bearer", bearer_format = "JWT" },
        { name = "apiKey", type = "apiKey", in = "header", header_name = "X-API-Key" }
    ],
    security = ["bearerAuth"],         // Optional document-level security
    tags = [                           // OpenAPI top-level tag descriptions
        { name = "users", description = "User operations" },
        { name = "admin", description = "Admin operations" }
    ],
    merge = [crate1::App1, crate2::App2]  // Merge child vespera apps
);
```

A relative `openapi` path resolves against the crate's `CARGO_MANIFEST_DIR`, so a workspace member writes the file next to its own `Cargo.toml`.

## OpenAPI `info` and `servers`

- `title` and `version` fill `info.title` / `info.version` (defaults: `"API"` and the crate's `CARGO_PKG_VERSION`).
- `info.description` defaults to the crate's `description` from `Cargo.toml`.
- Without `servers = [...]` (or `VESPERA_SERVER_URL`) the document has **no** `servers` entry, so Swagger UI and generated clients call the origin that serves the spec.
- `tags = [...]` adds top-level tag descriptions for the tags your routes use.

## Security Schemes

Declare schemes with `security_schemes`, then attach requirements to routes with `#[vespera::route(security = [...])]`. Each entry becomes an OpenAPI security requirement (with scopes for `("oauth2", ["read:users"])`, see below); `security = []` on a route emits an explicitly unauthenticated operation. A route referencing an unknown scheme is a compile error (checked after `merge`).

```rust
let app = vespera!(
    openapi = "openapi.json",
    docs_url = "/docs",
    security_schemes = [
        { name = "bearerAuth", type = "http", scheme = "bearer", bearer_format = "JWT" },
        { name = "apiKey", type = "apiKey", in = "header", header_name = "X-API-Key" },
        { name = "basicAuth", type = "http", scheme = "basic" }
    ],
    security = ["bearerAuth"] // optional document-level default
);

#[vespera::route(get, path = "/me", security = ["bearerAuth"])]
pub async fn current_user(...) -> ... { ... }

#[vespera::route(get, path = "/health", security = [])]
pub async fn health() -> &'static str { "ok" }
```

Supported `type` values are OpenAPI's camelCase wire names: `"apiKey"`, `"http"`, `"mutualTLS"`, `"oauth2"` and `"openIdConnect"`. The DSL uses `header_name` for the api-key `name` field so it does not clash with the scheme's own `name`.

### OAuth2 / OpenID Connect scopes

An `oauth2` scheme declares its `flows` (`implicit`, `password`,
`client_credentials`, `authorization_code`) with the URLs OpenAPI requires for
each flow and a `scopes` map; an `openIdConnect` scheme takes its discovery
URL. Requirements name scopes as a `("scheme", ["scope", ...])` tuple:

```rust
let app = vespera!(
    openapi = "openapi.json",
    security_schemes = [
        {
            name = "oauth2",
            type = "oauth2",
            flows = {
                authorization_code = {
                    authorization_url = "https://auth.example.com/authorize",
                    token_url = "https://auth.example.com/token",
                    refresh_url = "https://auth.example.com/refresh", // optional
                    scopes = { "read:users" = "Read users", "write:users" = "Modify users" },
                },
                client_credentials = {
                    token_url = "https://auth.example.com/token",
                    scopes = { "read:users" = "Read users" },
                },
            },
        },
        {
            name = "oidc",
            type = "openIdConnect",
            open_id_connect_url = "https://auth.example.com/.well-known/openid-configuration"
        }
    ],
    security = [("oauth2", ["read:users"])] // document-level default
);

// Alternatives (OR): an oauth2 token with `read:users`, or an OIDC login.
#[vespera::route(get, path = "/users", security = [("oauth2", ["read:users"]), ("oidc", ["openid"])])]
pub async fn list_users() -> ... { ... }

// AND group: an API key *and* an oauth2 token with `write:users`.
#[vespera::route(post, path = "/users", security = [["apiKey", ("oauth2", ["write:users"])]])]
pub async fn create_user() -> ... { ... }

// `[]` as an alternative makes authentication optional (`{}` in OpenAPI).
#[vespera::route(get, path = "/feed", security = ["bearerAuth", []])]
pub async fn feed() -> ... { ... }
```

```json
"security": [{ "oauth2": ["read:users"] }, { "oidc": ["openid"] }]
```

Checked at compile time: an `oauth2` scheme without `flows`, a flow missing
`authorization_url` / `token_url`, `flows` on a non-`oauth2` scheme, and a
requirement asking an `oauth2` scheme for a scope that none of its flows
declares are all compile errors. (OpenID Connect scopes live in the discovery
document and other scheme types take free-form role names, so those are not
checked.)

The scopes only *document* the requirement. When the host forwards the granted
scopes as `vespera::inprocess::Principal` authorities (feature `inprocess`),
`principal.require_scopes(&["read:users"])?` enforces them (an authority
`read:users` or Spring Security's `SCOPE_read:users` both count), answering `403`
with `WWW-Authenticate: Bearer error="insufficient_scope", scope="..."`.

## Environment Variable Fallbacks

Every parameter has a corresponding environment variable. The macro parameter takes priority over the env var, which takes priority over the built-in default.

| Parameter | Environment Variable | Default |
|-----------|---------------------|---------|
| `dir` | `VESPERA_DIR` | `"routes"` |
| `openapi` | `VESPERA_OPENAPI` | none |
| `title` | `VESPERA_TITLE` | `"API"` |
| `version` | `VESPERA_VERSION` | `CARGO_PKG_VERSION` |
| `docs_url` | `VESPERA_DOCS_URL` | none |
| `redoc_url` | `VESPERA_REDOC_URL` | none |
| `spec_url` | `VESPERA_SPEC_URL` | none |
| `servers` | `VESPERA_SERVER_URL` + `VESPERA_SERVER_DESCRIPTION` | none |

The `info` arguments (`description`, `summary`, `terms_of_service`, `contact_*`, `license*`) have no environment-variable fallback.

## API Info

`description`, `summary`, `terms_of_service`, `contact_name`, `contact_url`, `contact_email`, `license`, `license_name` and `license_url` fill the OpenAPI 3.1 `info` object.

- **`license`** is an SPDX expression and becomes `info.license.identifier` (and the `name`, unless `license_name` overrides it).
- A non-SPDX license uses **`license_name` + `license_url`**. OpenAPI 3.1 makes `identifier` and `url` mutually exclusive, so `license` with `license_url`, or `license_url` without `license_name`, is a compile error.
- `terms_of_service`, `contact_url` and `license_url` must be `http(s)://` URLs and `contact_email` must look like an address.
- Without `description`, `info.description` is the crate's `description` from `Cargo.toml`.

```rust
let app = vespera!(
    title = "Pet Store",
    summary = "Pets",
    contact_email = "api@example.com",
    license = "Apache-2.0"
);
```

## Documentation Endpoints

`docs_url`, `redoc_url` and `spec_url` each add an opt-in `GET` route. Every path must start with `/`, and no two of them may share a path — both mistakes are compile errors.

- **`docs_url`** serves Swagger UI and **`redoc_url`** serves ReDoc. Their assets load from unpkg at exact pinned versions with Subresource Integrity (`integrity` + `crossorigin="anonymous"`), so a tampered CDN file is refused by the browser. The spec is embedded in the page and escaped for the `<script>` context, so `</script>` or `<!--` inside a description or example cannot break the page.
- **`spec_url`** serves the generated OpenAPI document — including `merge`d apps — as `application/json`, ready for client generators and API gateways. The docs pages keep embedding the spec instead of fetching `spec_url`, so they still work when the router is nested under a prefix.

```rust
let app = vespera!(
    docs_url = "/docs",
    redoc_url = "/redoc",
    spec_url = "/openapi.json"
);
```

The pinned asset versions are `swagger-ui-dist` 5.34.0 and `redoc` 2.5.4; a page behind a Content Security Policy must allow those unpkg URLs. The renderers are public in `vespera::docs` if you want to serve a page yourself:

| Item | Description |
|------|-------------|
| `swagger_ui_html(spec_json: &str) -> String` | Swagger UI page with the spec embedded |
| `redoc_html(spec_json: &str) -> String` | ReDoc page with the spec embedded |
| `escape_json_for_script(json: &str) -> String` | Escapes `<`, `>`, `&`, U+2028 and U+2029 so JSON is safe inside `<script>` |
| `SWAGGER_UI_VERSION` / `REDOC_VERSION` | The pinned asset versions |

## Common Patterns

### Minimal — just a router

```rust
let app = vespera!();
```

### With Swagger UI

```rust
let app = vespera!(docs_url = "/docs");
```

### Write OpenAPI file + Swagger UI

```rust
let app = vespera!(
    openapi = "openapi.json",
    docs_url = "/docs",
    title = "My API",
    version = "1.0.0"
);
```

### Multiple OpenAPI output files

```rust
let app = vespera!(
    openapi = ["openapi.json", "docs/api-spec.json"]
);
```

### Custom route folder

```rust
// Scans src/api/ instead of src/routes/
let app = vespera!(dir = "api");
```

### With state and middleware

```rust
let app = vespera!(docs_url = "/docs")
    .with_state(AppState { db: pool })
    .layer(CorsLayer::permissive())
    .layer(TraceLayer::new_for_http());
```

### Merging child apps

```rust
let app = vespera!(
    openapi = "openapi.json",
    docs_url = "/docs",
    merge = [billing::BillingApp, notifications::NotificationsApp]
)
.with_state(app_state);
```

## The `.serve()` Extension

`vespera!()` returns an `axum::Router`. Vespera adds a `.serve(addr)` extension trait that replaces the usual `TcpListener::bind` + `axum::serve(...)` boilerplate:

```rust
use vespera::{vespera, Serve};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    vespera!(docs_url = "/docs")
        .serve("0.0.0.0:3000")
        .await
}
```

`addr` accepts anything `tokio::net::ToSocketAddrs` takes — strings like `"0.0.0.0:3000"`, tuples like `("127.0.0.1", 8080)`, or a `SocketAddr`.

The router is served with `ConnectInfo<SocketAddr>`, so handlers can extract the peer address with `ConnectInfo(addr): ConnectInfo<SocketAddr>`.

`serve_with_graceful_shutdown(addr, signal)` stops accepting connections once `signal` resolves and returns after in-flight requests finish:

```rust
use vespera::{vespera, Serve};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    vespera!(docs_url = "/docs")
        .serve_with_graceful_shutdown("0.0.0.0:3000", async {
            // requires tokio's `signal` feature
            let _ = tokio::signal::ctrl_c().await;
        })
        .await
}
```

To serve a listener you bound yourself, use `serve_listener(listener)` / `serve_listener_with_graceful_shutdown(listener, signal)`. Bind port `0` and read the assigned port before serving (tests: no bind-drop-rebind race, and a client may connect right away), or hand over a socket configured with `tokio::net::TcpSocket`:

```rust
use vespera::{vespera, Serve};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await?;
    println!("listening on {}", listener.local_addr()?);
    vespera!(docs_url = "/docs").serve_listener(listener).await
}
```

## export_app! Macro

Export a Vespera app from a library crate so it can be merged into a parent app:

```rust
// In the child crate's src/lib.rs
mod routes;

// Scans "routes" folder by default
vespera::export_app!(MyApp);

// Or with a custom directory
vespera::export_app!(MyApp, dir = "api");
```

This generates a struct with two associated items:
- `MyApp::OPENAPI_SPEC: &'static str` — the OpenAPI JSON spec as a static string
- `MyApp::router() -> Router` — a function returning the Axum router

The parent app merges it with `merge = [MyApp]` in `vespera!()`.

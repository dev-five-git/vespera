# Changelog

Release notes for every published package (the `vespera*` crates on
crates.io and `kr.devfive:vespera-bridge` / the Gradle plugin on Maven
Central) are generated by [changepacks](https://github.com/changepacks) from
the `.changepacks/changepack_log_*.json` entries merged into `main`, and are
published on the
[GitHub Releases](https://github.com/dev-five-git/vespera/releases) page.
This file only summarises breaking changes that need migration work; see the
[migration guide](https://vespera.devfive.kr/documentation/migration) for
details.

## 0.6.0 (unreleased)

A hardening release. Every item below can change behaviour or break the build
of an existing 0.5 application.

### OpenAPI (`vespera`, `vespera_macro`, `vespera_core`)

- Untagged enums emit `anyOf` instead of `oneOf`.
- Tuple / newtype structs, arrays and tuples get real array / inner schemas;
  `skip_serializing` / `skip_serializing_if` fields are no longer `required`.
- Internally tagged newtype variants, variant `skip` / `other` and
  `Arc` / `Rc` / `Cow` / `NonZero*` are supported; plain tuple returns and
  body-less `error_status` codes are documented.
- Colliding default `operationId`s are module-qualified.
- New compile errors: duplicate explicit `operation_id`s, unknown security
  schemes (checked after `merge`), malformed `#[schema(...)]`, and scalar
  payloads in internally tagged newtype variants.
- Known `headers::*` `TypedHeader` parameters use the real header name.
- `Path<Struct>` parameters are typed per field (serde names); `Query<Struct>`
  drops `skip` / `skip_deserializing` fields, expands `flatten`, and array
  fields carry `style: form, explode: true` (`vespera_core::Parameter` gained
  `style` / `explode`).
- `impl IntoResponse` / `Response` / `Redirect` responses are description-only;
  `Html<T>` is `text/html`, `Sse` is `text/event-stream`, `Bytes` / `Vec<u8>`
  bodies are `application/octet-stream`; `Option<Json<T>>` request bodies are
  `required: false`.
- `#[garde(...)]` rules on a `#[derive(Schema, garde::Validate)]` type are
  documented: `length` (`chars` mode, or `min = 1`; item / property counts),
  `range`, `email` / `url` / `ip*`, `pattern` / `prefix` / `suffix` /
  `contains` / `ascii`, and `inner(...)` on `items` now appear in the schema,
  and `#[schema(...)]` / `#[garde(...)]` rules on `Query<Struct>` /
  `Path<Struct>` fields reach the parameter schemas. Explicit `#[schema(...)]`
  keywords win; snapshots of such types change.
- `serde_json::Value` is `{}`, `std::time::Duration` is `{secs, nanos}`;
  `{*rest}` wildcards are documented as `{rest}`.
- `IpAddr`, `SocketAddr` (and `V4` / `V6`) and `PathBuf` are `string`.
  `Ipv4Addr` / `Ipv6Addr` are `string` with `format: ipv4` / `ipv6`, and
  `url::Url` is `string` with `format: uri`. These fields no longer need a
  `Schema` impl. A user `Schema` type with the same name keeps its `$ref`.
- Fields converted by `#[serde(with / serialize_with / deserialize_with)]` are
  documented as `{}` with a description instead of their Rust type (e.g. a
  `ts_seconds` `DateTime` was a date-time string, but is an integer on the
  wire). New `#[schema(value_type = T)]` documents the real shape, on fields
  and on containers. Container `#[serde(into = "T")]` documents responses as
  `T`, and `from` / `try_from` documents requests (`{Name}Input`) as `T`. An
  `Option` read by a custom deserializer is `required` in requests. The
  derive's `Schema` assertion checks `value_type` instead of the field type.
- SeaORM `Json` / `JsonValue` columns are `{}` (they hold any JSON value, not
  only objects; previously `type: object`), and `schema_type!` maps
  `JsonValue` to `serde_json::Value`. `Json<T>` is still treated as axum's
  wrapper.
- `flatten` on an `Option<T>` makes `T`'s fields optional; an enum's
  `rename_all` no longer renames struct-variant fields (as in serde);
  `rename_all_fields` and `deny_unknown_fields` are supported.

### Routing and build output (`vespera_macro`)

- **Served URLs:** an explicit `#[route(path = "/my_route")]` is used verbatim
  (no longer kebab-cased to `/my-route`); only segments derived from file and
  module names are kebab-cased.
- A relative `openapi = "..."` path resolves against the crate's
  `CARGO_MANIFEST_DIR` (workspace members write next to their own
  `Cargo.toml`); the cache directory honours `CARGO_TARGET_DIR`.
- `#[cron]` jobs start once per process (repeated `create_app()` calls no
  longer duplicate schedulers) and run on a dedicated thread when no Tokio
  runtime is present.

### Cargo features (`vespera`, `vespera_macro`)

- Multipart support (`vespera::multipart`, `vespera::tempfile`,
  `#[derive(Multipart)]`, `schema_type!(..., multipart)`) is behind the new
  `multipart` feature. It is **default-on**, so default builds are unaffected;
  **breaking only for `default-features = false` builds that use multipart** —
  add `features = ["multipart"]` (without it `#[derive(Multipart)]` is a
  compile error naming the feature). Dropping it removes tempfile, multer,
  encoding_rs and their dependencies; `axum-extra/multipart` moved from the
  default list into the feature.

### Documentation UI (`vespera`, `vespera_macro`, `vespera_core`)

- `docs_url` / `redoc_url` pages load `swagger-ui-dist` 5.34.0 and `redoc`
  2.5.4 at exact versions with SRI (`integrity` + `crossorigin="anonymous"`)
  instead of the latest unpkg release; pages behind a CSP must allow those
  unpkg URLs. The embedded spec is escaped for the `<script>` context, so
  `</script>` or `<!--` in a description or example no longer breaks the page.
  The renderers are public in the new `vespera::docs` module.
- New opt-in `vespera!(spec_url = "/openapi.json")` (env `VESPERA_SPEC_URL`)
  serves the generated, merged spec as `application/json`.
- `docs_url` / `redoc_url` / `spec_url` must start with `/` and be distinct;
  violations are compile errors (previously an axum panic at startup).

### `Serve`

- `serve()` provides `ConnectInfo<SocketAddr>`; the `Serve` trait gained
  `serve_with_graceful_shutdown(addr, signal)` (breaking for custom
  implementors).

### Cron hardening (`vespera`, `vespera_macro`, `vespera_core`)

Existing `#[vespera::cron("...")]` jobs keep their syntax and schedule; the
items below are additions, plus one behaviour change to graceful shutdown.

- **Time zones:** jobs are evaluated in **UTC** (unchanged, now documented);
  `#[vespera::cron("0 0 9 * * *", tz = "Asia/Seoul")]` evaluates one in an
  IANA zone. Needs the new opt-in `cron-tz` feature (adds `chrono-tz`); the
  name is checked at compile time, and `tz` without the feature is a compile
  error.
- **Overlap policy:** `overlap = "skip"` skips (and logs) a tick while the
  previous run of the job is still going; the default stays `"allow"`.
- **Panics:** every run is supervised, so a panicking job is logged to stderr
  (`vespera: cron job `module::function` panicked: …`) instead of vanishing
  with a dropped `JoinHandle`; the schedule keeps going.
- **Shutdown:** new `vespera::cron::shutdown()` (stop scheduling, process-wide
  and permanent) and `vespera::cron::shutdown_and_wait(timeout)` (also wait
  for in-flight runs). **Behaviour change:** `serve_with_graceful_shutdown`
  now calls both — no new cron runs once its signal resolves, and after the
  server drained, in-flight runs get up to `cron::DEFAULT_SHUTDOWN_GRACE`
  (10 s) before it returns.
- `CronJob` gained the `with_name`, `with_timezone` and `with_overlap`
  builders (used by the `vespera!` expansion), and `cron::Overlap`.

### OpenAPI accuracy (`vespera`, `vespera_macro`, `vespera_core`)

- No default `servers: [{url: "http://localhost:3000"}]`; `servers` is omitted
  unless configured. `info.description` defaults to the crate description.
- Handler doc comments: the first paragraph becomes `summary`, the rest
  `description` (previously the whole comment was the `description`).
- `#[schema(name = "X")]` types are referenced as `$ref X` everywhere.
- Recursive generic instantiations become components named
  `Base_Arg` (`Tree<i32>` → `Tree_i32`); non-recursive generics stay inline.
- `Result<(), E>` / `()` document an empty `200` without content; 1-argument
  `axum::response::Result<T>` and user `Result` aliases are expanded; unknown
  return types get a description-only `200` instead of `{type: object}`.
- `rename_all` follows serde exactly for fields vs. variants (`XMLParser` →
  `xMLParser` with `camelCase`); `rename(serialize, deserialize)` sides are
  never mixed; per-variant `#[serde(untagged)]` is supported.
- Doc comments keep Markdown indentation; `#[deprecated]` handlers / fields,
  `skip_deserializing` (`readOnly`) and `skip_serializing` (`writeOnly`) are
  documented; query/path field docs become parameter descriptions.
- Request bodies reference a `{Name}Input` component when serde reads the
  type differently than it writes it (`#[serde(default)]`, one-sided
  `skip_deserializing` / `skip_serializing`, `rename(deserialize = ..)`, or a
  field type with its own input view); `{Name}` stays the response view and
  nothing extra is emitted when the views are identical.
- `Query<T>` honours container `#[serde(default)]` and `Option<Query<T>>`
  (optional parameters) and destructured / `_` patterns.
- New compile errors: `#[route(responses = [(404, T)])]` with a `T` that does
  not implement `Schema`, and `#[route]` handlers inside inline `mod { .. }`
  blocks. `#[cfg]`-gated route modules / handlers that are compiled out are
  skipped.

### OpenAPI info, webhooks, encoding (`vespera`, `vespera_macro`, `vespera_core`)

- New optional `vespera!` arguments fill the `info` object: `description`
  (overrides the `Cargo.toml` description), `summary`, `terms_of_service`,
  `contact_name` / `contact_url` / `contact_email`, and `license` (SPDX →
  `identifier`) or `license_name` + `license_url`. Invalid URLs / emails and
  `license` combined with `license_url` are compile errors.
- `vespera_core::openapi::OpenApi` gained `webhooks` (OpenAPI 3.1, omitted
  when `None`; `merge` unions it self-wins) and `vespera_core::route::MediaType`
  gained `encoding` (new `Encoding` type). `vespera!` leaves both unset; they
  exist for post-processing. Struct literals of these types must add the new
  fields. `Info` now serializes `summary` before `description`.

### `Validated<T>`

- `Json` / `Form` / `Query` / `Path` deserialization failures now return
  `422` with the `{"errors":[{"path","message"}]}` envelope instead of axum's
  plain-text rejection.
- A `Validated<...>` argument that follows a `Path<T>` argument now documents
  the `422` response. `ValidatedWith<C, T>` arguments now document their wrapped
  body or query parameters and the `422` response. Both were previously missing
  from the spec.
- New compile error: a `Validated` / `ValidatedWith` payload without
  `garde::Validate`, such as a `Schema` struct with no runtime `#[schema(...)]`
  rule, or an enum. It is reported at the argument (`` `T` cannot be validated
  by `Validated` / `ValidatedWith` ``) rather than as a `Handler` trait-bound
  error. Such code never compiled; only the message changes.

### In-process / JNI (`vespera_inprocess`, `vespera_jni`)

- `SYNC` / `DIRECT` dispatch runs on the shared Tokio runtime (no per-thread
  runtimes); its blocking pool is capped at 512 threads by default.
- Default limits: 64 MiB buffered request (`413`), 256 MiB buffered response
  (`500`), 4096 in-flight `dispatchAsync` calls (`503`); optional dispatch
  timeout (`504`) and streamed-request cap. Set a limit to `0` to disable it.
- Streaming dispatch hoists `422` validation errors and reports failures after
  the first body byte as `IOException` instead of a synthetic `500`.
- Header values cross the wire as Latin-1 (one char per byte) in both
  directions; non-ASCII response header values are no longer dropped.
- Optional `remote_addr` / `scheme` request wire fields become
  `ConnectInfo<SocketAddr>` (feature `connect-info`, on via `vespera`) and
  `Extension<Scheme>`; a caught panic sets `metadata.panicked`; after
  `shutdown0` / `VesperaBridge.shutdown(Duration)` every dispatch answers
  `503`.

### Java bridge (`kr.devfive:vespera-bridge`)

- Spring is a provided dependency (Spring Boot 3.5 and 4 supported); declare
  `spring-boot-starter-web` / `jackson-databind` yourself.
- `HEAD` responses keep the real `Content-Length`.
- The native library is extracted per user, permission-checked and
  content-addressed (`vespera.native.dir` / `VESPERA_NATIVE_DIR`).
- New `vespera.bridge.native.*` properties; the new `configure*` methods return
  `boolean`.
- The bridge JAR and the native library must come from the same release.
- The app-selection header (`X-Vespera-App`) is client-controlled: restrict it
  with `vespera.bridge.exposed-apps`; it is no longer forwarded to Rust.
- Form-urlencoded bodies consumed by Spring filters are rebuilt from the
  request parameters.
- Responses carry `X-Request-Id` by default (`vespera.bridge.request-id.*`).
- The forwarded path drops the servlet context path, a prefix servlet mapping
  and `;` path parameters (e.g. `;jsessionid`).
- `ASYNC` responses get no `Range` handling.
- Errors generated by the proxy itself are `text/plain` (same shape as Rust's
  `error_wire`) instead of Spring error pages; the unknown-app `404` no longer
  echoes the requested name.
- Gradle plugin: `publishPlugins` fails without Plugin Portal credentials;
  `cargoBuild` is a `CargoBuildTask` instead of an `Exec` (builds that
  configure it as `Exec` must be updated); a missing `Cargo.lock` is accepted.

### Java bridge hardening (`kr.devfive:vespera-bridge`, Gradle plugin)

Behaviour changes — no code change is needed, but they are observable:

- An oversized `SYNC` / `ASYNC` response answers `500` instead of `413`, and
  `vespera.bridge.max-buffered-response-bytes` (default 64 MiB) is forwarded to
  the native buffered-response cap unless that cap is set explicitly.
- CORS preflights are routed to the Rust router by default
  (`vespera.bridge.cors=rust`); set `vespera.bridge.cors=spring` to keep Spring
  MVC's preflight handling. Duplicate `Access-Control-*` headers are resolved in
  favour of the configured owner.
- Unexpected proxy errors answer the fixed body `vespera dispatch failed`
  (details only in the WARN log), and writing a proxy error keeps headers set by
  servlet filters.
- `DispatchEvent.app()`, the `app` metric tag and the WARN log report `UNKNOWN`
  for client-selected app names not known to be registered.
- A missing native library answers `503` instead of throwing
  `UnsatisfiedLinkError`; a new `vespera` Actuator health indicator reports it.
- `VesperaBridge.init` fails when the native library's `major.minor` differs
  from the bridge's (`-Dvespera.native.versionCheck=warn|off`); this needs a
  native library exporting `nativeVersion0` (older ones only log a warning).
- On Windows, an extraction directory that is not owned by the current user or
  whose ACL lets other principals write is replaced by a fresh random one.
- `proxy(...)` returns a `DeferredResult` for `ASYNC`.
- Gradle plugin: hyphenated `crateName`s work (new `packageName` / `libName`),
  `bridgeVersion` defaults to the matching bridge release, `cargoSourceRoots` is
  ignored and `CargoBuildTask.commands` was replaced by its properties.

### Java bridge: proxied paths and IDE metadata (`kr.devfive:vespera-bridge`)

Additive; the defaults keep the previous behaviour.

- New `vespera.bridge.include-patterns` (default `/**`) and
  `vespera.bridge.exclude-patterns` (default none), in Spring `PathPattern`
  syntax. Paths outside them are not mapped to the proxy and fall through to
  the rest of Spring MVC (other controllers, static resources, then `404`);
  `cors=rust` preflights follow the same patterns.
- The JAR ships `META-INF/spring-configuration-metadata.json`: IDE completion,
  descriptions and value hints for every `vespera.bridge.*` property and
  `management.health.vespera.enabled`.

### musl native libraries (`kr.devfive:vespera-bridge`, Gradle plugin)

- On a musl-libc Linux JVM (Alpine) the bridge looks for the bundled library
  in `native/linux-<arch>-musl/` first; it falls back to the glibc
  `native/linux-<arch>/` library only when no musl one is bundled, with a WARN.
  The libc is detected from `/proc/self/maps` (no process spawn) and can be
  forced with `-Dvespera.native.libc=musl|glibc`. glibc JVMs are unchanged.
- Gradle plugin: a `*-linux-musl*` target triple is bundled under
  `native/linux-<arch>-musl/` even when its `targets` key is the plain
  `linux-<arch>` (previously `native/linux-<arch>/`); `linux-<arch>-musl` keys
  are accepted, and on a musl build host the host build goes to the `-musl`
  folder. A jar built this way needs a bridge from this release to load the
  musl library on Alpine.

### Cancel on disconnect (`vespera_inprocess`, `vespera_jni`, `kr.devfive:vespera-bridge`)

- `dispatchAsync` cancellation reaches Rust: when its `CompletableFuture`
  completes exceptionally (`cancel(..)`, `orTimeout(..)`, an external
  `completeExceptionally(..)`) the Rust handler future is dropped at its next
  `.await` and its `vespera.async.maxInFlight` slot is released (previously
  the handler ran to completion and its result was discarded).
- The proxy's `ASYNC` mode cancels the native dispatch when the servlet async
  request ends first (Spring async timeout, a container-reported error or
  client disconnect): the timed-out handler no longer keeps running.
- `VesperaBridge.dispatchAsync` is now a Java method (same signature) over the
  new package-private `AsyncDispatch` natives; the JNI symbol
  `VesperaBridge.dispatchAsync` is replaced by `AsyncDispatch.dispatch0`
  (returns a cancellation token) and `AsyncDispatch.cancel0`. As before, the
  bridge JAR and the native library must come from the same release.
- New `vespera_inprocess::{cancellable, cancel, cancellable_in_flight}`
  (host-driven cancellation of a spawned dispatch future) and
  `vespera_jni::async_in_flight()` (current `dispatchAsync` slot count).
- Streaming modes already stop on a failed client write (the response body is
  dropped as soon as the servlet `OutputStream` throws, including on the
  flush before the body waits); this is now covered by tests. `SYNC` /
  `DIRECT` dispatches cannot observe a disconnect before the handler returns
  (the response is only written afterwards); bound them with
  `vespera.dispatch.timeoutMillis`.

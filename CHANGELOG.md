# Changelog

Release notes for every published package (the `vespera*` crates on
crates.io and `kr.devfive:vespera-bridge` / the Gradle plugin on Maven
Central) are generated by [changepacks](https://github.com/changepacks) from
the `.changepacks/changepack_log_*.json` entries merged into `main`, and are
published on the
[GitHub Releases](https://github.com/dev-five-git/vespera/releases) page.
This file only summarises breaking changes that need migration work; see the
[migration guide](https://vespera.devfive.kr/documentation/migration) for
details.

## 0.6.0 (unreleased)

A hardening release. Every item below can change behaviour or break the build
of an existing 0.5 application.

### OpenAPI (`vespera`, `vespera_macro`, `vespera_core`)

- Untagged enums emit `anyOf` instead of `oneOf`.
- Tuple / newtype structs, arrays and tuples get real array / inner schemas;
  `skip_serializing` / `skip_serializing_if` fields are no longer `required`.
- Internally tagged newtype variants, variant `skip` / `other` and
  `Arc` / `Rc` / `Cow` / `NonZero*` are supported; plain tuple returns and
  body-less `error_status` codes are documented.
- Colliding default `operationId`s are module-qualified.
- New compile errors: duplicate explicit `operation_id`s, unknown security
  schemes (checked after `merge`), malformed `#[schema(...)]`, and scalar
  payloads in internally tagged newtype variants.
- Known `headers::*` `TypedHeader` parameters use the real header name.
- `Path<Struct>` parameters are typed per field (serde names); `Query<Struct>`
  drops `skip` / `skip_deserializing` fields, expands `flatten`, and array
  fields carry `style: form, explode: true` (`vespera_core::Parameter` gained
  `style` / `explode`).
- `impl IntoResponse` / `Response` / `Redirect` responses are description-only;
  `Html<T>` is `text/html`, `Sse` is `text/event-stream`, `Bytes` / `Vec<u8>`
  bodies are `application/octet-stream`; `Option<Json<T>>` request bodies are
  `required: false`.
- `serde_json::Value` is `{}`, `std::time::Duration` is `{secs, nanos}`;
  `{*rest}` wildcards are documented as `{rest}`.
- `flatten` on an `Option<T>` makes `T`'s fields optional; an enum's
  `rename_all` no longer renames struct-variant fields (as in serde);
  `rename_all_fields` and `deny_unknown_fields` are supported.

### Routing and build output (`vespera_macro`)

- **Served URLs:** an explicit `#[route(path = "/my_route")]` is used verbatim
  (no longer kebab-cased to `/my-route`); only segments derived from file and
  module names are kebab-cased.
- A relative `openapi = "..."` path resolves against the crate's
  `CARGO_MANIFEST_DIR` (workspace members write next to their own
  `Cargo.toml`); the cache directory honours `CARGO_TARGET_DIR`.
- `#[cron]` jobs start once per process (repeated `create_app()` calls no
  longer duplicate schedulers) and run on a dedicated thread when no Tokio
  runtime is present.

### `Serve`

- `serve()` provides `ConnectInfo<SocketAddr>`; the `Serve` trait gained
  `serve_with_graceful_shutdown(addr, signal)` (breaking for custom
  implementors).

### OpenAPI accuracy (`vespera`, `vespera_macro`, `vespera_core`)

- No default `servers: [{url: "http://localhost:3000"}]`; `servers` is omitted
  unless configured. `info.description` defaults to the crate description.
- Handler doc comments: the first paragraph becomes `summary`, the rest
  `description` (previously the whole comment was the `description`).
- `#[schema(name = "X")]` types are referenced as `$ref X` everywhere.
- Recursive generic instantiations become components named
  `Base_Arg` (`Tree<i32>` → `Tree_i32`); non-recursive generics stay inline.
- `Result<(), E>` / `()` document an empty `200` without content; 1-argument
  `axum::response::Result<T>` and user `Result` aliases are expanded; unknown
  return types get a description-only `200` instead of `{type: object}`.
- `rename_all` follows serde exactly for fields vs. variants (`XMLParser` →
  `xMLParser` with `camelCase`); `rename(serialize, deserialize)` sides are
  never mixed; per-variant `#[serde(untagged)]` is supported.
- Doc comments keep Markdown indentation; `#[deprecated]` handlers / fields,
  `skip_deserializing` (`readOnly`) and `skip_serializing` (`writeOnly`) are
  documented; query/path field docs become parameter descriptions.
- `Query<T>` honours container `#[serde(default)]` and `Option<Query<T>>`
  (optional parameters) and destructured / `_` patterns.
- New compile errors: `#[route(responses = [(404, T)])]` with a `T` that does
  not implement `Schema`, and `#[route]` handlers inside inline `mod { .. }`
  blocks. `#[cfg]`-gated route modules / handlers that are compiled out are
  skipped.

### `Validated<T>`

- `Json` / `Form` / `Query` / `Path` deserialization failures now return
  `422` with the `{"errors":[{"path","message"}]}` envelope instead of axum's
  plain-text rejection.

### In-process / JNI (`vespera_inprocess`, `vespera_jni`)

- `SYNC` / `DIRECT` dispatch runs on the shared Tokio runtime (no per-thread
  runtimes); its blocking pool is capped at 512 threads by default.
- Default limits: 64 MiB buffered request (`413`), 256 MiB buffered response
  (`500`), 4096 in-flight `dispatchAsync` calls (`503`); optional dispatch
  timeout (`504`) and streamed-request cap. Set a limit to `0` to disable it.
- Streaming dispatch hoists `422` validation errors and reports failures after
  the first body byte as `IOException` instead of a synthetic `500`.
- Header values cross the wire as Latin-1 (one char per byte) in both
  directions; non-ASCII response header values are no longer dropped.
- Optional `remote_addr` / `scheme` request wire fields become
  `ConnectInfo<SocketAddr>` (feature `connect-info`, on via `vespera`) and
  `Extension<Scheme>`; a caught panic sets `metadata.panicked`; after
  `shutdown0` / `VesperaBridge.shutdown(Duration)` every dispatch answers
  `503`.

### Java bridge (`kr.devfive:vespera-bridge`)

- Spring is a provided dependency (Spring Boot 3.5 and 4 supported); declare
  `spring-boot-starter-web` / `jackson-databind` yourself.
- `HEAD` responses keep the real `Content-Length`.
- The native library is extracted per user, permission-checked and
  content-addressed (`vespera.native.dir` / `VESPERA_NATIVE_DIR`).
- New `vespera.bridge.native.*` properties; the new `configure*` methods return
  `boolean`.
- The bridge JAR and the native library must come from the same release.
- The app-selection header (`X-Vespera-App`) is client-controlled: restrict it
  with `vespera.bridge.exposed-apps`; it is no longer forwarded to Rust.
- Form-urlencoded bodies consumed by Spring filters are rebuilt from the
  request parameters.
- Responses carry `X-Request-Id` by default (`vespera.bridge.request-id.*`).
- The forwarded path drops the servlet context path, a prefix servlet mapping
  and `;` path parameters (e.g. `;jsessionid`).
- `ASYNC` returns `ResponseEntity<byte[]>` (no `Range` handling).
- Errors generated by the proxy itself are `text/plain` (same shape as Rust's
  `error_wire`) instead of Spring error pages; the unknown-app `404` no longer
  echoes the requested name.
- Gradle plugin: `publishPlugins` fails without Plugin Portal credentials;
  `cargoBuild` is a `CargoBuildTask` instead of an `Exec` (builds that
  configure it as `Exec` must be updated); a missing `Cargo.lock` is accepted.
